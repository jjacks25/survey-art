# infra/

One-time AWS bootstrap for land-survey-scraper. **Manual operator tool — not run in CI.**

## What it provisions

`cloudformation/bootstrap.yaml`, deployed via `bootstrap.py`:

- **IAM user** `land-survey-scraper-deploy` — scoped to CloudFormation deploy actions,
  the bootstrap S3 bucket, and the bootstrap secret only. No `AdministratorAccess`.
- **S3 bucket** — versioned, SSE-S3 encrypted, all public access blocked. Name is
  auto-generated by CloudFormation (not chosen up front). Intended to hold future
  CloudFormation templates for `TemplateURL`-based deploys + change sets.
- **Secrets Manager secret** (default name `land-survey-scraper/deploy-credentials`) —
  holds the deploy user's `AccessKeyId` / `SecretAccessKey`, written by `bootstrap.py`
  after the stack is created (CloudFormation only exposes a new access key's secret
  value once, in Outputs, immediately after creation).

This first stack is deployed via `TemplateBody` (template content sent directly in the
API call) because the S3 bucket it creates doesn't exist yet to host it as
`TemplateURL`. Every later stack should deploy via `TemplateURL` against that bucket.

## Running it

Requires an operator AWS identity with privileges to create IAM users/policies — this
is broader than the scoped deploy-user policy the stack creates, by design (you can't
bootstrap a least-privilege user with that same user's own permissions).

```bash
# Validate the template only, no AWS resources created
uv run python infra/bootstrap.py --dry-run --region us-west-2

# Deploy
uv run python infra/bootstrap.py --region us-west-2

# Optional: specific AWS profile, custom stack/secret names
uv run python infra/bootstrap.py --profile my-profile --stack-name my-stack --secret-name my/secret
```

Safe to re-run — `bootstrap.py` detects an existing stack and updates it; an identical
template produces a no-op ("No updates are to be performed") rather than an error.

## Security notes

- Credentials are never printed or logged by `bootstrap.py` — only resource names/ARNs.
- Retrieve the deploy user's access key only via `aws secretsmanager get-secret-value`,
  not from CloudFormation stack Outputs after the fact (the secret value is only
  available in Outputs at creation/update time).
- Rotate the deploy user's access key periodically: create a new `AWS::IAM::AccessKey`
  resource (or run `aws iam create-access-key` + update the secret), then delete the old
  key once nothing depends on it.
